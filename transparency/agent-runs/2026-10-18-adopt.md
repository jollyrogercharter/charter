## Facts checked before designing

- `api.github.com` and `raw.githubusercontent.com` both answer `Access-Control-Allow-Origin: *` (checked with `curl -I` on 2026-10-18). A browser can therefore read public evidence directly, and no backend is needed.
- The anonymous GitHub API limit is 60 requests per hour per IP address (`x-ratelimit-*` headers). The design uses 3 API requests per assessment, confirmed live.

## Decisions

- **Collect, then evaluate.** All network work produces a *snapshot*: the file list and key files at one commit. Evaluation is a pure function of the snapshot, so any assessment can be reproduced offline, and web, agent and CLI results can be compared byte for byte.
- **Absence is not violation.** Checks are `found`, `not-found`, `contradicted`, `not-checked` or `not-applicable`. Demonstrated problems are *concerns*, listed apart from gaps. `not-applicable` comes only from the project's own manifest. The data pillar is `unknown`, never `missing`, without a manifest.
- **Prepare, don't publish.** Every generated file is new-files-only, carries `REPLACE:` markers, never sets `evidenced` and never fills in the assessor. GitHub links prefill content, but the developer signs in and confirms on GitHub.
- **Never execute repository code.** Only the challenge's *discover* step is checked automatically. Steps that need a build are `not-attempted`, with the reason.
- **Raise the Flag kept.** `/adopt/` previously held the *Raise the Flag* text, which now sits below the tool, unchanged apart from heading levels. Whether it should move to its own page is left to the human.

## Independent review (Claude Sonnet) and fixes

A Sonnet reviewer reproduced 12 defects in 02ce402, with a script for each. All are fixed. Each fix has a regression test (`review:` in `test/adopt.test.mjs`), and every one of those tests was confirmed to fail on 02ce402 and pass after the fix.

1. **`source.repository` in a "local" snapshot was unvalidated.** It flowed into the Markdown report and GitHub links. Local snapshots now can't carry one, unknown `source` keys are rejected, and refs and branches use the same `validRef` as fetching.
2. **Path names could inject content:**
   - `](…)` could retarget Markdown links (now escaped as entities);
   - Unicode tag, filler and other format characters weren't treated as hidden (now they are, in paths and in manifest strings);
   - sentence-like directory names were cited as evidence (now they aren't).
   The docs claim "no repository prose is copied" was corrected: contents never are, paths are filtered.
3. **Deeply nested `costs.json` or `jrc.json` crashed the assessment** with a stack overflow. Now each check fails closed to `not-checked`.
4. **CODEOWNERS:**
   - a team was counted as a single owner and reported as a contradiction;
   - email owners were ignored;
   - truncated files were judged on their first owner.
5. **Unread or truncated files were treated as absence.** This affected README, CODEOWNERS, package manifests and deployment docs. They are now `not-checked`.
6. **An unreadable tree said "jrc.json absent, create one", and a bad ref returned a report instead of an error.** Now the manifest is `unknown`, the first roadmap step is `rescan`, and a 404/422 on the commit (or a redirect) returns `NOT_FOUND`.
7. **C-OVERCLAIM was raised when the scan merely couldn't tell.** It's now raised only on a complete tree, for `missing` or `partially-evidenced`.
8. **False "found":**
   - `## Usage` counted as build instructions, which could pass the challenge's discovery step;
   - `license-checker.js` counted as a licence;
   - generic "migrating" docs counted as data export;
   - symlinks counted as files.
9. **SPDX parsing:** `AND` and `OR` precedence was ignored, so `(MIT OR Apache-2.0) AND SSPL-1.0` read as free. Mentions of other licences inside MIT text read as non-free. Zlib with "All rights reserved" read as non-free. There's now a real expression parser, and licence text is classified by its title area first.
10. **Collector selection:**
    - `README` was read instead of `README.md`;
    - `doc/DEPLOY.md` was never read;
    - nested `node_modules` exhausted the local entry cap.
11. **`jrc assess --out` overwrote existing files, and a missing directory like `docs/api` was fetched from GitHub as a repository.** `--out` now refuses to overwrite, and a positional argument is treated as a repository only with a `github.com/` prefix.
12. **Snapshot refs with `..` could retarget the GitHub links to another repository.**

The reviewer's speculative notes were also addressed:

- Fetches use `redirect: "manual"`, so a redirect is never followed to another host; it's reported as `moved`.
- Raw-file 403/429 responses aren't cached.

The TOCTOU symlink swap in the local collector is noted but not fixed. It needs a hostile local filesystem, and the collector only reads files in the user's own checkout.

## What the live demo found about this repository

At `feat/webmcp`, three pillars were evidenced, two partly, and data was not applicable (self-reported). The roadmap starts with `CONTRIBUTING`, a second independent steward and `SECURITY.md`. These are real gaps, and they were left for the human to decide: who answers security reports, and who the second steward is, aren't decisions an agent can make.

## Heuristic corrections made during the run

The first live run marked build instructions and the governance document as missing here. Neither was correct: `DEPLOYMENT.md` has a "Build locally" section, and governance lives in `community/GOVERNANCE-AND-DEBATE.md`. The checks now read build headings in deployment documents and match governance and contributing documents anywhere. Paths under vendored or fixture directories are ignored, so the wider matching doesn't count other projects' files; there's a test for this.
