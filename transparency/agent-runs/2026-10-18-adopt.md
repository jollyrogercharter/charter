## Facts checked before designing

- `api.github.com` and `raw.githubusercontent.com` both answer `Access-Control-Allow-Origin: *` (checked with `curl -I` on 2026-10-18). A browser can therefore read public evidence directly, and no backend is needed.
- The anonymous GitHub API limit is 60 requests per hour per IP address (`x-ratelimit-*` headers). The design uses 3 API requests per assessment, confirmed live.

## Decisions

- **Collect, then evaluate.** All network work produces a *snapshot*: the file list and key files at one commit. Evaluation is a pure function of the snapshot, so any assessment can be reproduced offline, and web, agent and CLI results can be compared byte for byte.
- **Absence is not violation.** Checks are `found`, `not-found`, `contradicted`, `not-checked` or `not-applicable`. Demonstrated problems are *concerns*, listed apart from gaps. `not-applicable` comes only from the project's own manifest. The data pillar is `unknown`, never `missing`, without a manifest.
- **Prepare, don't publish.** Every generated file is new-files-only, carries `REPLACE:` markers, never sets `evidenced` and never fills in the assessor. GitHub links prefill content, but the developer signs in and confirms on GitHub.
- **Never execute repository code.** Only the challenge's *discover* step is checked automatically. Steps that need a build are `not-attempted`, with the reason.
- **Raise the Flag kept.** `/adopt/` previously held the *Raise the Flag* text, which now sits below the tool, unchanged apart from heading levels. Whether it should move to its own page is left to the human.

## What the live demo found about this repository

At `feat/webmcp`, three pillars were evidenced, two partly, and data was not applicable (self-reported). The roadmap starts with `CONTRIBUTING`, a second independent steward and `SECURITY.md`. These are real gaps, and they were left for the human to decide: who answers security reports, and who the second steward is, aren't decisions an agent can make.

## Heuristic corrections made during the run

The first live run marked build instructions and the governance document as missing here. Neither was correct: `DEPLOYMENT.md` has a "Build locally" section, and governance lives in `community/GOVERNANCE-AND-DEBATE.md`. The checks now read build headings in deployment documents and match governance and contributing documents anywhere. Paths under vendored or fixture directories are ignored, so the wider matching doesn't count other projects' files; there's a test for this.
