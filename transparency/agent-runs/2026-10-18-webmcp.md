## Sources checked before designing

- WebMCP Draft Community Group Report, 16 October 2026: `document.modelContext`, the `registerTool` IDL, annotations, error conditions, signals.
- Chrome developer docs: overview (origin trial from 149, `#enable-webmcp-testing`), imperative API (`execute(input, { signal })`, unregistering by signal, string input deprecated in 155), secure tools (`untrustedContentHint`, output-size guidance).

## Decisions

- **One engine, many front ends.** `lib/jrc/check.mjs` was split into a pure `core.mjs` plus a filesystem *probe*. The CLI uses the Node probe. The browser uses a probe that reports file evidence as `not-checked`, so a web assessment can never claim to have verified a file it couldn't read. `report.mjs` takes the hash as a parameter (Node `crypto` or WebCrypto). The existing 43 CLI, site and ledger tests passed unchanged after the split.
- **Data from the repository, not a copy.** The browser bundle and `/api/v1/*.json` are built from `CHARTER.md`, `OPEN-DEPENDENCIES.md`, `status.json`, `costs.json` and the provenance manifest on every build, by the same capability functions the tools call.
- **`basis` on every fact:** verified, self-reported, missing, estimate, not-applicable or historical. Status items count as self-reported even when "implemented", because they're the project's own records.
- **Small outputs.** Defaults are summaries plus references, about 1.3–2K characters, near Chrome's ~1.5K guidance; filters return detail.
- **Read-only only.** No tool changes state, so `consequentialHint` is false everywhere and no confirmation flow was needed.
- **No origin-trial token.** Registering for the trial needs a Google account, so that's the owner's decision. The layout emits the meta tag if a token is configured.
