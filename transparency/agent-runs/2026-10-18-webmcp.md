## Sources checked before designing

- Chrome developer docs: overview (origin trial from 149, `#enable-webmcp-testing`), imperative API (`execute(input, { signal })`, unregistering by signal, string input deprecated in 155), secure tools (`untrustedContentHint`, output-size guidance).

## Decisions

- **One engine, many front ends.** `lib/jrc/check.mjs` was split into a pure `core.mjs` plus a filesystem *probe*. The CLI uses the Node probe. The browser uses a probe that reports file evidence as `not-checked`, so a web assessment can never claim to have verified a file it couldn't read. `report.mjs` takes the hash as a parameter (Node `crypto` or WebCrypto). The existing 43 CLI, site and ledger tests passed unchanged after the split.
- **Data from the repository, not a copy.** The browser bundle and `/api/v1/*.json` are built from `CHARTER.md`, `OPEN-DEPENDENCIES.md`, `status.json`, `costs.json` and the provenance manifest on every build, by the same capability functions the tools call.
- **`basis` on every fact:** verified, self-reported, missing, estimate, not-applicable or historical. Status items count as self-reported even when "implemented", because they're the project's own records.
- **Small outputs.** Defaults are summaries plus references, about 1.3–2K characters, near Chrome's ~1.5K guidance; filters return detail.
- **Read-only only.** No tool changes state, so `consequentialHint` is false everywhere and no confirmation flow was needed.
- **No origin-trial token.** Registering for the trial needs a Google account, so that's the owner's decision. The layout emits the meta tag if a token is configured.

## Independent review (Claude Sonnet) and fixes

The reviewer reproduced 10 problems in commit 5a24516. All are fixed, each with a regression test confirmed to fail on 5a24516 and pass after the fix:

1. **Unread file evidence counted as solid.** Manifests whose evidence files don't exist showed "5/5 evidenced" with a `self-reported` basis, and the plan advised pinning files that were already pinned. Now the basis is `unchecked`, the summary counts unread items, and the plan's first step is to run `jrc check` locally.
2. **ReDoS.** A 64 KiB string took about 4.1 s to scan, because of the email regex's unbounded local part. It now takes about 20 ms. This was in the shared engine, so the CLI was affected too.
3. **Unbounded output.** Echoed manifest text could produce 40–56K-character results, with manifest gaps appearing as the tool's own advice. Echoes are now clipped, wrapped as untrusted, and kept out of advice fields, with a hard 8K output cap.
4. **ZIP digest.** The unpublished ZIP's digest was labelled `verified`, with a `git show` command that can't work. It's now `self-reported`, with an accurate explanation.
5. **Hash naming.** `manifest_sha256` hashed canonical JSON, not file bytes. It's renamed `canonical_json_sha256` and documented.
6. **Pre-aborted signal.** A pre-aborted registration signal still registered all tools, and outer-signal listeners were never released. Both are fixed.
7. **Prototype names.** `constructor`, `toString` and `__proto__` passed `additionalProperties: false`. The validator now uses own properties only.
8. **Pseudo-negations.** Affirming phrases ("No doubt certified", "Not only certified") bypassed the wording filter. The negation rule now requires adjacency, with a list of false negations. This applied to the CLI too.
9. **Self-asserted independence.** The plan treated claimed independence as done. It now asks for the public reviewer report, and pillars carry `independence_verified: false`.
10. **Bundle and costs.** A malformed bundle was cached forever; it's now validated and retried. Unmeasured hours showed as `0`; they're now `null`.
