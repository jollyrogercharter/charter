# Quick Start for Human and Claude

1. Give Claude **this entire repository ZIP** and paste or attach `CLAUDE-LAUNCH-HANDOFF.md`.
2. Let Claude read all docs and prepare an execution checklist in `launch/LAUNCH-STATUS.md`.
3. Sign in to GitHub yourself and authorize Claude to guide UI setup; choose the free organization and secure 2FA. First choice `jollyrogercharter`, with live checks and fallbacks.
4. Let Claude build the Eleventy static site and preview it using free hosting while final domain availability is checked.
5. Review the registrar's **actual price and renewal terms** before any domain purchase. Own the domain yourself.
6. Review all public release artifacts, especially any existing personal data, uploaded attachments and the full founding conversation. Do **not** hand over a whole ChatGPT account export for public posting.
7. Publish a curated archive immediately if approved, but label the verbatim full transcript pending until a human-approved single-conversation source is ready.
8. Approve initial GitHub Discussions/RFCs and a factual, clearly AI-assisted launch post; then invite criticism and independent reproductions.
9. Have Claude generate `DEPLOYMENT.md`, `OPEN-DEPENDENCIES.md`, a zero-spend marketing report, and a final proof-of-work ledger with real URLs.

What should *not* delay non-sensitive work: specific domain choice, final trademark decision, unready billing APIs or incomplete ATProto implementation. Label these honestly and keep building the reproducible static first release.

## Source record and timestamp prerequisites

- Human: request a ChatGPT data export or explicitly review and share an approved founding-conversation snapshot. Keep the whole account ZIP **private**.
- Claude: extract only the target conversation in a protected local environment, record exact metadata available and gaps, then generate a sanitized public edition and documented redaction log **for human approval**.
- Claude: calculate the SHA-256 of the exact approved published bytes, issue portable OpenTimestamps proof, track `not-requested`/`pending`/`verified`, upgrade/verify it when actually possible, and publish independent verification instructions and release manifest. No backdated origin claim.
- Site: add `/provenance/` with actual proof state and distinctions among integrity, independent existence-by-time, and authorship claims.
- Every future substantial agent-driven change: log prompts/decisions, tests, human approval, costs, version and release hashes, with privacy/safety filtering.
